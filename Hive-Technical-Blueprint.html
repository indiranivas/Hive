1. Product Vision & Scope

What Hive Is

A passive AI agent that absorbs a team's entire work trail — emails, calls, tasks, Git commits — and builds a live, queryable knowledge layer. Two surfaces: a Teams chatbot for everyone and a web dashboard for managers.

Core Capabilities

CapabilityDescriptionSurface
Natural language Q&AAsk anything about the team's work, get a sourced answerTeams bot
Proactive dependency routingWhen you're assigned a task, Hive tells you who's touched related code/modulesTeams bot
Auto status reportsWeekly per-person status generated from commits, tickets, PRs, emailsDashboard
Expertise map"Who at the company knows X?" with evidenceBoth
Knowledge Request frameworkDetect gaps → route to expert → capture answer → permanent repoTeams bot
Team pulse & analyticsActivity bars, blocker flags, knowledge gap analyticsDashboard

What Hive Does NOT Do

  • Write — no sending emails, updating tickets, pushing code, or posting messages on behalf of users
  • Monitor individuals — no keystroke tracking, no sentiment scoring, no "productivity" ranking
  • Make decisions — surfaces information, never acts on it

4. Data Models & Schemas

Core Entities (PostgreSQL)

people

CREATE TABLE people (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    azure_ad_id     VARCHAR(128) UNIQUE NOT NULL,
    email           VARCHAR(256) UNIQUE NOT NULL,
    display_name    VARCHAR(256) NOT NULL,
    team_id         UUID REFERENCES teams(id),
    role            VARCHAR(32) DEFAULT 'member',   -- 'member' | 'manager' | 'admin'
    created_at      TIMESTAMPTZ DEFAULT now(),
    updated_at      TIMESTAMPTZ DEFAULT now()
);

teams

CREATE TABLE teams (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    name            VARCHAR(256) NOT NULL,
    org_id          UUID REFERENCES orgs(id),
    manager_id      UUID REFERENCES people(id),
    created_at      TIMESTAMPTZ DEFAULT now()
);

work_artifacts — the universal record

CREATE TABLE work_artifacts (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    source          VARCHAR(32) NOT NULL,    -- 'email' | 'call' | 'task' | 'git'
    source_id       VARCHAR(512) NOT NULL,   -- external ID (message-id, commit SHA, etc.)
    author_id       UUID REFERENCES people(id),
    team_id         UUID REFERENCES teams(id),
    artifact_type   VARCHAR(64) NOT NULL,    -- 'email_thread' | 'meeting_transcript' |
                                             -- 'work_item' | 'commit' | 'pull_request' |
                                             -- 'pr_review' | 'comment'
    title           TEXT,
    content         TEXT NOT NULL,            -- full text content
    metadata        JSONB DEFAULT '{}',       -- flexible: {repo, branch, ticket_id, attendees, ...}
    occurred_at     TIMESTAMPTZ NOT NULL,     -- when the artifact was created in the source
    ingested_at     TIMESTAMPTZ DEFAULT now(),
    UNIQUE (source, source_id)
);

CREATE INDEX idx_artifacts_author ON work_artifacts(author_id);
CREATE INDEX idx_artifacts_team ON work_artifacts(team_id);
CREATE INDEX idx_artifacts_type ON work_artifacts(artifact_type);
CREATE INDEX idx_artifacts_occurred ON work_artifacts(occurred_at DESC);
CREATE INDEX idx_artifacts_metadata ON work_artifacts USING GIN(metadata);

expertise_scores

CREATE TABLE expertise_scores (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    person_id       UUID REFERENCES people(id),
    topic           VARCHAR(256) NOT NULL,   -- 'salesforce-api' | 'react' | 'billing-service'
    score           FLOAT DEFAULT 0.0,       -- computed from artifact frequency + recency
    evidence_count  INT DEFAULT 0,           -- number of artifacts backing this
    last_seen       TIMESTAMPTZ,             -- most recent artifact on this topic
    updated_at      TIMESTAMPTZ DEFAULT now(),
    UNIQUE (person_id, topic)
);

CREATE INDEX idx_expertise_topic ON expertise_scores(topic);
CREATE INDEX idx_expertise_score ON expertise_scores(score DESC);

knowledge_requests

CREATE TABLE knowledge_requests (
    id              UUID PRIMARY KEY DEFAULT gen_random_uuid(),
    requester_id    UUID REFERENCES people(id) NOT NULL,
    question        TEXT NOT NULL,
    context         TEXT,                     -- what they were working on when they asked
    status          VARCHAR(32) DEFAULT 'open',  -- 'open' | 'routed' | 'answered' | 'indexed'
    routed_to_id    UUID REFERENCES people(id),
    answer          TEXT,
    answered_by_id  UUID REFERENCES people(id),
    answered_at     TIMESTAMPTZ,
    tags            TEXT[] DEFAULT '{}',      -- topic tags for indexing
    related_artifacts UUID[] DEFAULT '{}',   -- links to work_artifacts
    created_at      TIMESTAMPTZ DEFAULT now(),
    updated_at      TIMESTAMPTZ DEFAULT now()
);

CREATE INDEX idx_kr_status ON knowledge_requests(status);
CREATE INDEX idx_kr_tags ON knowledge_requests USING GIN(tags);

CREATE TABLE status_reports (

5. Ingestion Pipeline (4 Streams)

Architecture pattern: Each connector runs as a Celery scheduled task (every 5–15 min) AND listens for real-time webhooks where available. Webhooks give instant updates; scheduled pulls catch anything webhooks miss.

import httpx
from msgraph import GraphServiceClient

GRAPH_BASE = "https://graph.microsoft.com/v1.0"

async def fetch_emails(mailbox: str, since: datetime) -> list[dict]:
    """Fetch emails from the shared Hive mailbox since last check."""
    url = f"{GRAPH_BASE}/users/{mailbox}/messages"
    params = {
        "$filter": f"receivedDateTime ge {since.isoformat()}",
        "$select": "id,subject,bodyPreview,body,from,toRecipients,"
                   "ccRecipients,receivedDateTime,conversationId",
        "$orderby": "receivedDateTime desc",
        "$top": 50
    }
    # Paginate through all results
    messages = []
    async with httpx.AsyncClient() as client:
        while url:
            resp = await client.get(url, headers=auth_headers(), params=params)
            data = resp.json()
            messages.extend(data.get("value", []))
            url = data.get("@odata.nextLink")
            params = None  # nextLink includes params
    return messages

def normalize_email(msg: dict, team_id: str) -> WorkArtifact:
    """Convert Graph API email to WorkArtifact."""
    return WorkArtifact(
        source="email",
        source_id=msg["id"],
        author_id=resolve_person(msg["from"]["emailAddress"]["address"]),
        team_id=team_id,
        artifact_type="email_thread",
        title=msg["subject"],
        content=strip_html(msg["body"]["content"]),
        metadata={
            "conversation_id": msg["conversationId"],
            "to": [r["emailAddress"]["address"] for r in msg["toRecipients"]],
            "cc": [r["emailAddress"]["address"] for r in msg["ccRecipients"]],
        },
        occurred_at=msg["receivedDateTime"],
    )

5.3 Task / Backlog Connector

Source: Azure DevOps REST API

# Azure DevOps PAT with Work Items (Read) scope
ADO_BASE = "https://dev.azure.com/{org}/{project}/_apis"

async def fetch_work_items(since: datetime) -> list[dict]:
    """Fetch recently updated work items via WIQL."""
    wiql = {
        "query": f"""
        SELECT [System.Id], [System.Title], [System.State],
               [System.AssignedTo], [System.ChangedDate],
               [System.Description], [System.Tags],
               [System.WorkItemType], [System.IterationPath]
        FROM WorkItems
        WHERE [System.ChangedDate] >= '{since.strftime('%Y-%m-%d')}'
        ORDER BY [System.ChangedDate] DESC
        """
    }
    resp = await client.post(f"{ADO_BASE}/wit/wiql?api-version=7.1", json=wiql)
    ids = [item["id"] for item in resp.json()["workItems"]]

    # Batch fetch full work items (max 200 per call)
    items = []
    for batch in chunks(ids, 200):
        resp = await client.get(
            f"{ADO_BASE}/wit/workitems?ids={','.join(map(str, batch))}"
            f"&$expand=relations&api-version=7.1"
        )
        items.extend(resp.json()["value"])
    return items

def normalize_work_item(item: dict, team_id: str) -> WorkArtifact:
    fields = item["fields"]
    return WorkArtifact(
        source="task",
        source_id=str(item["id"]),
        author_id=resolve_person(fields.get("System.AssignedTo", {}).get("uniqueName")),
        team_id=team_id,
        artifact_type="work_item",
        title=fields["System.Title"],
        content=f"{fields['System.Title']}\n\nState: {fields['System.State']}\n"
                f"Type: {fields['System.WorkItemType']}\n"
                f"Description: {strip_html(fields.get('System.Description', ''))}",
        metadata={
            "state": fields["System.State"],
            "work_item_type": fields["System.WorkItemType"],
            "iteration": fields.get("System.IterationPath"),
            "tags": fields.get("System.Tags", "").split("; "),
            "priority": fields.get("Microsoft.VSTS.Common.Priority"),
            "ado_url": item["url"],
        },
        occurred_at=fields["System.ChangedDate"],
    )

async def fetch_commits(repo_id: str, since: datetime) -> list[dict]:
    url = f"{ADO_BASE}/git/repositories/{repo_id}/commits"
    params = {
        "searchCriteria.fromDate": since.isoformat(),
        "api-version": "7.1",
        "$top": 100
    }
    resp = await client.get(url, params=params)
    return resp.json()["value"]

async def fetch_pull_requests(repo_id: str, since: datetime) -> list[dict]:
    url = f"{ADO_BASE}/git/repositories/{repo_id}/pullrequests"
    params = {
        "searchCriteria.status": "all",
        "api-version": "7.1",
        "$top": 50
    }
    resp = await client.get(url, params=params)
    # Filter by date client-side
    return [pr for pr in resp.json()["value"]
            if parse_dt(pr["creationDate"]) >= since]

def normalize_commit(commit: dict, repo_name: str, team_id: str) -> WorkArtifact:
    return WorkArtifact(
        source="git",
        source_id=commit["commitId"],
        author_id=resolve_person(commit["author"]["email"]),
        team_id=team_id,
        artifact_type="commit",
        title=commit["comment"].split("\n")[0][:200],
        content=commit["comment"],
        metadata={
            "repo": repo_name,
            "sha": commit["commitId"],
            "files_changed": commit.get("changeCounts", {}),
            "url": commit["remoteUrl"],
        },
        occurred_at=commit["author"]["date"],
    )

def normalize_pr(pr: dict, repo_name: str, team_id: str) -> WorkArtifact:
    return WorkArtifact(

            "reviewers": [r["uniqueName"] for r in pr.get("reviewers", [])],

embed_model = SentenceTransformer("all-MiniLM-L6-v2")  # 384-dim, fast
# For production: "BAAI/bge-large-en-v1.5" (1024-dim, more accurate)

def chunk_content(content: str, max_tokens: int = 512) -> list[str]:
    """Split content into overlapping chunks for embedding."""
    sentences = content.split(". ")
    chunks, current = [], []
    current_len = 0
    for sent in sentences:
        word_count = len(sent.split())
        if current_len + word_count > max_tokens and current:
            chunks.append(". ".join(current) + ".")
            # 20% overlap
            overlap = max(1, len(current) // 5)
            current = current[-overlap:]
            current_len = sum(len(s.split()) for s in current)
        current.append(sent)
        current_len += word_count
    if current:
        chunks.append(". ".join(current))
    return chunks

async def embed_and_store(artifact: WorkArtifact):
    """Chunk, embed, and store in vector DB + relational DB."""
    # 1. Save to PostgreSQL
    await db.work_artifacts.insert(artifact)

    # 2. Chunk and embed
    chunks = chunk_content(artifact.content)
    embeddings = embed_model.encode(chunks)

    # 3. Store in ChromaDB
    collection = chroma_client.get_or_create_collection("hive_artifacts")
    for i, (chunk, embedding) in enumerate(zip(chunks, embeddings)):
        collection.add(
            ids=[f"{artifact.id}_{i}"],
            embeddings=[embedding.tolist()],
            documents=[chunk],
            metadatas=[{
                "artifact_id": str(artifact.id),
                "source": artifact.source,
                "artifact_type": artifact.artifact_type,
                "author_id": str(artifact.author_id),
                "author_name": artifact.author_name,
                "team_id": str(artifact.team_id),
                "occurred_at": artifact.occurred_at.isoformat(),
                "title": artifact.title or "",
                "chunk_index": i,
            }]
        )

    # 4. Update expertise scores
    topics = extract_topics(artifact.content)  # LLM or keyword extraction
    await update_expertise(artifact.author_id, topics, artifact.occurred_at)

async def answer_query(
    query: str,
    user_id: str,
    team_id: str | None = None,
    scope: str = "team"  # "team" | "org"
) -> QueryResponse:
    """
    Main Q&A pipeline:
    1. Embed the query
    2. Retrieve relevant chunks from vector DB
    3. Filter by access scope
    4. Send to LLM with context
    5. Return sourced answer
    """
    # 1. Embed query
    query_embedding = embed_model.encode(query).tolist()

    # 2. Retrieve from vector DB
    collection = chroma_client.get_collection("hive_artifacts")
    where_filter = {"team_id": team_id} if scope == "team" else {}
    results = collection.query(
        query_embeddings=[query_embedding],
        n_results=15,
        where=where_filter if where_filter else None,
    )

    # Also search knowledge repo
    kr_collection = chroma_client.get_collection("hive_knowledge_repo")
    kr_results = kr_collection.query(
        query_embeddings=[query_embedding],
        n_results=5,
    )

    # 3. Build context
    context_chunks = format_context(results, kr_results)

    # 4. Send to LLM
    response = await llm.chat(
        system=QUERY_SYSTEM_PROMPT,
        messages=[{
            "role": "user",
            "content": f"""Question: {query}

Context from team's work trail:
{context_chunks}

Rules:
- Answer ONLY from the provided context
- Cite the source for every claim (commit SHA, ticket ID, email subject, meeting date)
- If the context doesn't contain the answer, say so clearly
- Suggest raising a Knowledge Request if the gap is significant
- Name specific people when relevant
"""
        }]
    )

    # 5. Log the query
    await db.query_log.insert(QueryLog(
        user_id=user_id,
        query_text=query,
        response_text=response.text,
        sources_used=extract_sources(results),
        surface="teams",
    ))

    return QueryResponse(
        answer=response.text,
        sources=extract_sources(results),
        has_gap=response.text contains "Knowledge Request",
    )

async def generate_weekly_status(person_id: str, team_id: str,
                                  week_start: date, week_end: date) -> StatusReport:
    """Generate a weekly status report from work artifacts."""
    # 1. Fetch all artifacts for this person in the date range
    artifacts = await db.work_artifacts.query(
        author_id=person_id,
        occurred_at_gte=week_start,
        occurred_at_lte=week_end,
    )

    # 2. Group by type
    commits = [a for a in artifacts if a.artifact_type == "commit"]
    prs = [a for a in artifacts if a.artifact_type == "pull_request"]
    tickets = [a for a in artifacts if a.artifact_type == "work_item"]
    emails = [a for a in artifacts if a.artifact_type == "email_thread"]
    meetings = [a for a in artifacts if a.artifact_type == "meeting_transcript"]

    # 3. Send to LLM for summarization
    response = await llm.chat(
        system=STATUS_SYSTEM_PROMPT,
        messages=[{
            "role": "user",
            "content": f"""Generate a concise weekly status for {person.display_name}.
Week: {week_start} to {week_end}

Commits ({len(commits)}):
{format_commits(commits)}

Pull Requests ({len(prs)}):
{format_prs(prs)}

Tickets touched ({len(tickets)}):
{format_tickets(tickets)}

Email threads ({len(emails)}):
{format_email_summaries(emails)}

Meetings ({len(meetings)}):
{format_meeting_summaries(meetings)}

Rules:
- 3-5 bullet points max
- Lead with completed work, then in-progress, then blockers
- Every claim must reference a specific artifact (commit SHA, ticket ID, PR number)
- Flag anything blocked for 3+ days
- No fluff, no praise — just facts
"""
        }]
    )

    # 4. Store
    report = StatusReport(
        person_id=person_id,
        team_id=team_id,
        period_start=week_start,
        period_end=week_end,
        summary=response.text,
        evidence=[{"artifact_id": str(a.id), "type": a.artifact_type}
                  for a in artifacts[:20]],
    )
    await db.status_reports.insert(report)
    return report

6.3 Expertise Mapper

async def update_expertise(person_id: str, topics: list[str], occurred_at: datetime):
    """Update expertise scores based on new artifact."""
    for topic in topics:
        existing = await db.expertise_scores.get(person_id=person_id, topic=topic)
        if existing:
            # Decay old score, boost with new evidence
            recency_weight = 1.0 / max(1, (datetime.now() - occurred_at).days / 30)
            new_score = existing.score * 0.95 + recency_weight * 0.3
            await db.expertise_scores.update(
                id=existing.id,
                score=new_score,
                evidence_count=existing.evidence_count + 1,
                last_seen=occurred_at,
            )
        else:
            await db.expertise_scores.insert(ExpertiseScore(
                person_id=person_id,
                topic=topic,
                score=1.0,
                evidence_count=1,
                last_seen=occurred_at,
            ))

async def find_experts(topic: str, limit: int = 5) -> list[ExpertResult]:
    """Find people with expertise on a topic."""
    # Combine exact match + semantic search
    exact = await db.expertise_scores.query(
        topic_like=f"%{topic}%",
        order_by="score DESC",
        limit=limit
    )

    # Also search vector DB for semantic matches
    embedding = embed_model.encode(topic).tolist()
    vector_results = chroma_client.get_collection("hive_artifacts").query(
        query_embeddings=[embedding],
        n_results=50,
    )

    # Aggregate by author
    author_counts = Counter()
    for meta in vector_results["metadatas"][0]:
        author_counts[meta["author_id"]] += 1

    # Merge and rank
    return merge_and_rank(exact, author_counts, limit)

6.4 Proactive Dependency Router

async def on_task_assigned(work_item: WorkArtifact, assignee_id: str):
    """
    Triggered when someone is assigned a task.
    Finds related experts and proactively notifies in Teams.
    """
    # 1. Extract key topics from the task
    topics = extract_topics(work_item.content + " " + str(work_item.metadata))

    # 2. Find people who've worked on related things
    related_people = []
    for topic in topics:
        experts = await find_experts(topic, limit=3)
        related_people.extend(experts)

    # 3. Find related artifacts (PRs, commits touching same modules)
    if "repo" in work_item.metadata:
        related_artifacts = await db.work_artifacts.query(
            metadata_contains={"repo": work_item.metadata["repo"]},
            artifact_type__in=["commit", "pull_request"],
            limit=10,
            order_by="occurred_at DESC",
        )
    else:
        related_artifacts = []

    # 4. Deduplicate and filter out the assignee themselves
    unique_experts = deduplicate([
        p for p in related_people if p.person_id != assignee_id
    ])

    if not unique_experts:
        return  # No relevant context to surface

    # 5. Send proactive message in Teams
    card = build_dependency_card(
        task=work_item,
        experts=unique_experts[:3],
        related_artifacts=related_artifacts[:5],
    )
    await teams_bot.send_proactive_message(
        user_id=assignee_id,
        card=card,
    )

7. Knowledge Request Framework

async def handle_knowledge_gap(query: str, user_id: str, context: str = "") -> KR:
    """
    Called when Hive can't answer a query OR user manually raises a KR.
    1. Create KR record
    2. Find best expert to route to
    3. Send notification to expert via Teams
    4. Track until answered
    """
    # 1. Create the knowledge request
    kr = await db.knowledge_requests.insert(KnowledgeRequest(
        requester_id=user_id,
        question=query,
        context=context,
        status="open",
        tags=extract_topics(query),
    ))

    # 2. Find best expert
    experts = []
    for tag in kr.tags:
        tag_experts = await find_experts(tag, limit=3)
        experts.extend(tag_experts)

    best_expert = rank_for_routing(experts)  # factors: score, recency, load

    if best_expert:
        # 3. Route to expert
        kr.status = "routed"
        kr.routed_to_id = best_expert.person_id
        await db.knowledge_requests.update(kr)

        # 4. Notify expert in Teams
        card = build_kr_card(kr, requester=await db.people.get(user_id))
        await teams_bot.send_proactive_message(
            user_id=best_expert.person_id,
            card=card,
        )
    else:
        # No expert found — notify manager or post to team channel
        await teams_bot.post_to_channel(
            team_id=await get_user_team(user_id),
            card=build_kr_open_card(kr),
        )

    return kr


async def handle_kr_answer(kr_id: str, answer: str, answered_by: str):
    """
    Called when an expert answers a Knowledge Request.
    1. Store answer
    2. Index in knowledge repo (vector DB)
    3. Notify requester
    4. Update expertise scores
    """
    kr = await db.knowledge_requests.get(kr_id)

    # 1. Store answer
    kr.answer = answer
    kr.answered_by_id = answered_by
    kr.answered_at = datetime.now()
    kr.status = "answered"
    await db.knowledge_requests.update(kr)

    # 2. Index in knowledge repo
    embedding = embed_model.encode(f"{kr.question}\n{kr.answer}").tolist()
    kr_collection = chroma_client.get_or_create_collection("hive_knowledge_repo")
    kr_collection.add(
        ids=[str(kr.id)],
        embeddings=[embedding],
        documents=[f"Q: {kr.question}\nA: {kr.answer}"],
        metadatas=[{
            "question": kr.question,
            "answer": kr.answer,
            "answered_by": answered_by,
            "tags": kr.tags,
            "created_at": kr.created_at.isoformat(),
        }]
    )
    kr.status = "indexed"
    await db.knowledge_requests.update(kr)

    # 3. Notify requester
    card = build_kr_answered_card(kr)
    await teams_bot.send_proactive_message(
        user_id=kr.requester_id,
        card=card,
    )

    # 4. Update expertise scores for the answerer
    await update_expertise(answered_by, kr.tags, datetime.now())


def rank_for_routing(experts: list[ExpertResult]) -> ExpertResult | None:
    """
    Rank experts for KR routing. Factors:
    - Expertise score (higher = better)
    - Recency (worked on topic recently = better)
    - Load (fewer open KRs routed to them = better)
    """
    for expert in experts:
        open_kr_count = db.knowledge_requests.count(
            routed_to_id=expert.person_id,
            status="routed",
        )
        expert.routing_score = (
            expert.score * 0.5 +
            expert.recency_weight * 0.3 -
            open_kr_count * 0.2
        )
    experts.sort(key=lambda e: e.routing_score, reverse=True)
    return experts[0] if experts else None

from botbuilder.core import TurnContext, ActivityHandler
from botbuilder.schema import Activity, Attachment

class HiveBot(ActivityHandler):

    async def on_message_activity(self, turn_context: TurnContext):
        text = turn_context.activity.text.strip()
        user_id = turn_context.activity.from_property.aad_object_id

        # Remove @Hive mention
        text = remove_mention(text, "Hive")

        # Route to handler
        if text.lower().startswith("kr ") or text.lower().startswith("knowledge request"):
            await self.handle_kr(turn_context, text, user_id)
        elif text.lower().startswith("who knows") or text.lower().startswith("who-knows"):
            await self.handle_who_knows(turn_context, text, user_id)
        elif text.lower().startswith("status"):
            await self.handle_status(turn_context, text, user_id)
        else:
            await self.handle_query(turn_context, text, user_id)

    async def handle_query(self, ctx: TurnContext, query: str, user_id: str):
        """General Q&A — the main interaction."""
        # Show typing indicator
        await ctx.send_activity(Activity(type="typing"))

        # Get answer from knowledge engine
        team_id = await get_user_team(user_id)
        result = await answer_query(query, user_id, team_id)

        # Build Adaptive Card response
        card = build_answer_card(
            question=query,
            answer=result.answer,
            sources=result.sources,
            has_gap=result.has_gap,
        )
        await ctx.send_activity(Activity(
            type="message",
            attachments=[Attachment(
                content_type="application/vnd.microsoft.card.adaptive",
                content=card,
            )]
        ))

    async def handle_who_knows(self, ctx: TurnContext, text: str, user_id: str):
        """Find experts on a topic."""
        topic = text.replace("who knows", "").replace("who-knows", "").strip(" ?")
        experts = await find_experts(topic, limit=5)

        card = build_expertise_card(topic, experts)
        await ctx.send_activity(Activity(
            type="message",
            attachments=[Attachment(
                content_type="application/vnd.microsoft.card.adaptive",
                content=card,
            )]
        ))

    async def handle_kr(self, ctx: TurnContext, text: str, user_id: str):
        """Raise a Knowledge Request."""
        question = text.replace("kr ", "").replace("knowledge request ", "").strip()
        kr = await handle_knowledge_gap(question, user_id)

        card = build_kr_submitted_card(kr)
        await ctx.send_activity(Activity(
            type="message",
            attachments=[Attachment(
                content_type="application/vnd.microsoft.card.adaptive",
                content=card,
            )]
        ))

    async def handle_status(self, ctx: TurnContext, text: str, user_id: str):
        """Get status for a person or team."""
        # Parse "status @PersonName" or "status team"
        target = text.replace("status", "").strip()
        team_id = await get_user_team(user_id)

        if not target or target == "team":
            statuses = await get_team_status(team_id)
            card = build_team_status_card(statuses)
        else:
            person = await resolve_person_from_name(target, team_id)
            status = await get_person_status(person.id)
            card = build_person_status_card(status)

        await ctx.send_activity(Activity(
            type="message",
            attachments=[Attachment(
                content_type="application/vnd.microsoft.card.adaptive",
                content=card,
            )]
        ))

11. Privacy & Guardrails

Non-negotiable principles:

  • Read-only. Hive never writes to any external system. No emails sent, no tickets updated, no code pushed.
  • No personal surveillance. No keystroke logging, no screen monitoring, no "productivity scores." Work artifacts only.
  • Scoped access. Members see their team. Managers see their team. Nobody sees up.
  • Full audit trail. Every query logged — who asked what, when, via which surface.
  • Data stays internal. If using cloud LLM APIs, use Azure OpenAI Service or Anthropic's enterprise tier with data processing agreements. For maximum security, self-host Mistral.

13. Phased Build Plan

Phase 1 — Foundation (Weeks 1–3)

Goal: Core pipeline working end-to-end with one data source

  • Set up project structure, Docker Compose, PostgreSQL, ChromaDB, Redis
  • Build the work_artifacts schema and Alembic migrations
  • Build the Git connector first (simplest API, richest signal)
  • Build normalizer + embedder pipeline
  • Build basic query engine (embed query → retrieve chunks → LLM answer)
  • Build a CLI interface for testing queries: python -m hive.cli "who worked on auth?"
  • Milestone: Ask a question about Git commits and get a sourced answer

Phase 2 — Teams Bot (Weeks 4–5)

Goal: @Hive is live in Teams, answering questions from Git data

  • Register Azure Bot, create Teams app manifest
  • Build bot message handler with query routing
  • Build Adaptive Cards for answers, sources, and "raise KR" button
  • Deploy bot to Azure (or ngrok for dev tunnel)
  • Sideload app in Teams for testing
  • Milestone: Type @Hive who wrote the most commits this week? in Teams and get an answer

Phase 3 — Task Connector + Status Generator (Weeks 6–7)

Goal: Azure DevOps data flowing in, auto-statuses generating

  • Build Azure DevOps work item connector (pull + webhook)
  • Build status generator — weekly per-person summaries from commits + tickets
  • Add status command to Teams bot
  • Build expertise scorer (compute topic scores from artifact history)
  • Add who-knows command to Teams bot
  • Milestone: Auto-generated weekly status for each team member, viewable in Teams

Phase 4 — Knowledge Request Framework (Weeks 8–9)

Goal: KR loop working — gap → route → answer → indexed

  • Build knowledge_requests table and API
  • Build gap detection (when query engine can't answer → offer KR)
  • Build expert routing logic (expertise scores + load balancing)
  • Build KR Adaptive Cards (submit, notify expert, answer form, confirmation)
  • Build knowledge repo indexing (answered KR → vector DB)
  • Test full loop: ask → gap → route → expert answers → next person gets instant answer
  • Milestone: Complete KR lifecycle working in Teams

Phase 5 — Email + Call Connectors (Weeks 10–12)

Goal: All four data streams flowing into Hive

  • Set up shared Hive mailbox, configure Graph API mail permissions
  • Build email connector with webhook subscriptions
  • Build call/meeting transcript connector (or manual upload fallback)
  • Enrich query engine with email + meeting context
  • Build proactive dependency routing (task assigned → surface related experts)
  • Milestone: Hive answers questions drawing from all four data streams

Phase 6 — Manager Dashboard (Weeks 13–16)

Goal: Full web dashboard live for managers

  • Set up Next.js project with Azure AD auth (MSAL)
  • Build Team Pulse page (overview, activity bars, alerts)
  • Build Status page (per-person cards with evidence drill-down)
  • Build Expertise Map page (interactive topic → people graph)
  • Build Knowledge Repo browser (search, filter by tag, browse answered KRs)
  • Build Gap Analytics page (open KRs, top topics, bus-factor alerts)
  • Build Settings page (team config, connector status, notification prefs)
  • Milestone: Manager logs in and sees full team picture without opening any other tool

Phase 7 — Production Hardening (Weeks 17–20)

Goal: Reliable, secure, monitored, ready for real team use

  • Switch ChromaDB → Qdrant for production vector search
  • Add monitoring (Prometheus + Grafana or Azure Monitor)
  • Add error handling, retry logic, circuit breakers on all connectors
  • Add rate limiting on LLM calls with cost tracking
  • Security audit — scope enforcement, input sanitization, token rotation
  • Load testing with realistic data volumes
  • Documentation — setup guide, admin guide, user guide
  • Milestone: Hive running on one real team, stable, monitored, costs tracked
